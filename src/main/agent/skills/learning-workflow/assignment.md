# 完成与检查作业

## 明确交付要求

教师指定的格式优先。没有明确格式要求时，默认提供可编辑原稿与 PDF；Markdown 原稿保存后可调用 `export_learning_pdf` 在同目录生成 PDF，不弹出保存对话框、不覆盖已有文件。已有 PDF 先检查内容，确需更新时用新的修订文件名。导出失败保留原稿并明确列为待处理项，不能称已交付完整。

读取实际题目及附件，提取题目、小问、范围、格式、截止时间和明确的评分要求。将每项可核对要求写入 `save_learning_task` 的 requirements，初始 status=draft、要求 status=open。同一作业查询后更新已有 id。

每个要求使用稳定 id，并关联最终的 deliverableIds 和 evidenceIds；成果路径位于课程 `作业/课程-作业名/` 或既有 `大作业/`。保留原题和附件。读取题目时记录 assignmentSourceId 与实际采用的 assignmentSourceVersion；来源版本来自 query_learning_sources，不在交付时静默换成最新版本。材料缺失、相互矛盾或无法读取时明确列为 open，不编造题干、标准答案或评分规则。

已有答案先读取并复核；内容和提交规范均满足时复用原件，不重复生成或覆盖。发现内容问题或不符合明确的提交规范时另存修订稿，保留原件并向用户简要说明改动。已有文件不算本次新生成的成果。

## 按学生作业组织提交稿

最终稿面向教师批阅，按题目要求作答。教师的模板、语言、篇幅和引用要求优先；没有模板时，以作业标题、原题编号和小问组织正文，不额外添加摘要、学习目标、知识点清单或自评。无需完整抄录题目，保留足够识别小问的标题与必要已知条件即可。

- 计算题写清变量、必要公式、关键代入、单位与结果；证明题给出条件和完整逻辑；论述题围绕问题形成有依据的论证。编程或实验题按要求交付代码、方法、真实结果和必要的运行说明。保留能让教师判断正确性的步骤，不写成授课讲义，也不为简短而跳过关键推导。
- 使用自然、准确的课程书面表达和本课符号，直接陈述解答。默认不写“这里用到了什么知识点”“对应课件第几页”“你需要理解”“下面我将为你”等辅导话语，不添加 AI 执行过程、资料检索经过、验证日志、哈希、置信度、自我评价或完成状态。涉及定理时可直接写出名称、条件并应用，不需要说明在哪份课件学到。不得伪造学生身份信息、个人经历、实验数据或“本人独立完成”等声明；课程要求的引用和 AI 使用说明照实保留。
- 将知识点定位、课件文件与页段、要求—成果—证据映射、独立复核报告存入学习记录和 workingDirectory，不作为提交稿章节或附录，也不混入最终 PDF。教师明确要求引用，或使用外部文献、数据、图表和直接引文时，保留必要的规范引用，不将此规则用于删除学术依据。
- 影响解答成立的假设、适用条件和限制必须写在相应答案中。待补材料、尚未验证的结论及交付缺口在任务结果中单独告知用户；有缺口的文件保持草稿状态，不靠删除提示把不完整答案包装成提交稿。

## 有依据地完成

- PDF、课件等文档先读 document-reading Skill，使用其 `prepare_document` 缓存流程按页段读取。核对当前小问所需的定义、算法或推导依据，不能只读题目页就声称核对了课件依据；记清实际文件页码与印刷页码，以及单位、期间和假设。读取时保存来源版本或输入 SHA256，不把最后重新取得的哈希当成最初已读版本。长任务先定简短顺序，逐题/逐章保存完整成果。
- 数值题把输入、公式和中间步骤保留为可复算过程，实际用计算工具运行并核对结果。检查正负号、量纲、税前税后、期初期末、百分比和基数；复算吻合不代表口径正确，仍需对原题。
- 论述题检查结论是否由给定依据支持，区分必要与充分条件、相关与因果、一般关系与附加假设。图表/公式抽取可疑时看原页。
- 阅读反馈、个人困惑和观点可写成供用户修改的拟稿；没有用户表达依据时，不宣称是其真实阅读经历或已经独立完成的计算。
- 用户要求 Markdown/PDF 等交付格式时沿用现有导出功能。PDF/DOCX 等排版成果（包括复用的已有答案）要查看实际渲染页面，短作业逐页检查并记录页码；抽出文字或生成图片不等于已经视觉检查。只有确认完整的最终文件才列为交付物。

## 复核并关闭问题

实质性作业完成后使用一次独立 `run_task_step` 复核。只传原题/要求清单、必要来源路径与页段、最终稿位置、上述学生作业提交稿规范和明确的检查范围；让其先按原题独立判断，再检查最终稿。复核结果写到 workingDirectory，返回可定位的问题、影响与建议，不整份复制答案，不向提交稿追加复核报告或知识点出处。

父会话读取独立报告正文，审阅实际检查范围、依据、问题与限制后再采纳结论。子任务的摘要和 completed 状态不能代替审阅报告。

复核覆盖：要求是否遗漏、来源是否支持结论、计算与单位/条件是否正确，以及最终稿的题号、小问、语言、篇幅和格式是否符合教师要求，是否混入不需要提交的教学说明或过程记录。来源检查可以使用内部证据，不以正文没有课件页码或知识点定位判定不合格。发现问题写入 findings=open，修正正文后逐项复查才能 closed；不只生成一份检查报告就结束。无数值任务可以把 calculations 标为 not_applicable，写清原因。

等待成果、报告和验证日志写入完成，读取并审阅最终证据，再用 `inspect_learning_files` 取得 SHA256（最多20文件一批），最后 `save_learning_task` 登记。同一文件的写入、读取、哈希和登记按此顺序执行，不并行；文件再改动后重新核对并取哈希。来源须与读取时版本一致，题目或关键资料变化后重新核对受影响内容。证据 description 写明原文件页段、题目位置或实际计算核验结果。登记时关联要求、成果和证据，传入实际已复核的 assignmentSourceVersion，填写 requirements/sources/calculations 三项 checks；通过的填 passed 并说明实际做过的检查。所有要求满足、文件版本一致、问题关闭后才能 status=checked。检查未通过就保留 draft，并交付已完成部分和影响结果的缺口。

学习中心的已复核表示已记录的检查通过，不保证答案绝对正确，也不代表 Canvas 已提交。课程截止时间/提交状态来自 Canvas，草稿完成状态独立记录；只有用户明确要求且流程允许才执行提交。未在线刷新时，将截止时间标为本地记录，不把旧的提交状态或尝试次数称为当前状态；只说明本次是否执行了提交。
