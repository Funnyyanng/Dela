# 完成与检查作业

## 明确交付要求

读取实际题目及附件，提取题目、小问、范围、格式、截止时间和明确的评分要求。将每项可核对要求写入 `save_learning_task` 的 requirements，初始 status=draft、要求 status=open。同一作业查询后更新已有 id。

每个要求使用稳定 id，并关联最终的 deliverableIds 和 evidenceIds；成果路径位于课程 `作业/课程-作业名/` 或既有 `大作业/`。保留原题和附件。读取题目时记录 assignmentSourceId 与实际采用的 assignmentSourceVersion；来源版本来自 query_learning_sources，不在交付时静默换成最新版本。材料缺失、相互矛盾或无法读取时明确列为 open，不编造题干、标准答案或评分规则。

## 有依据地完成

- 从当前小问涉及的课件和教材页段取证；公式、数据、特殊定义记清页码、单位、期间及假设。读取时保存来源版本或输入 SHA256，不把最后重新取得的哈希当成最初已读版本。长任务先定简短顺序，逐题/逐章保存完整成果。
- 数值题把输入、公式和中间步骤保留为可复算过程，实际用计算工具运行并核对结果。检查正负号、量纲、税前税后、期初期末、百分比和基数；复算吻合不代表口径正确，仍需对原题。
- 论述题检查结论是否由给定依据支持，区分必要与充分条件、相关与因果、一般关系与附加假设。图表/公式抽取可疑时看原页。
- 阅读反馈、个人困惑和观点可写成供用户修改的拟稿；没有用户表达依据时，不宣称是其真实阅读经历或已经独立完成的计算。
- 用户要求 Markdown/PDF 等交付格式时沿用现有导出功能。只有确认完整的最终文件才列为交付物；PDF/DOCX 等排版成果检查实际渲染，不能把成功生成等同于内容完整。

## 复核并关闭问题

实质性作业完成后使用一次独立 `run_task_step` 复核。只传原题/要求清单、必要来源路径与页段、最终稿位置和明确的检查范围；让其先按原题独立判断，再检查最终稿。复核结果写到 workingDirectory，返回可定位的问题、影响与建议，不整份复制答案。

复核覆盖：要求是否遗漏、来源是否支持结论、计算与单位/条件是否正确。发现问题写入 findings=open，修正正文后逐项复查才能 closed；不只生成一份检查报告就结束。无数值任务可以把 calculations 标为 not_applicable，写清原因。

最终对成果与证据使用 `inspect_learning_files` 取得当前 SHA256（最多20文件一批），来源须与读取时的版本一致；题目或关键资料变化后重新核对受影响内容。证据 description 写明原文件页段、题目位置或实际计算核验结果。`save_learning_task` 关联要求、成果和证据，传入实际已复核的 assignmentSourceVersion，填写 requirements/sources/calculations 三项 checks；通过的填 passed 并说明实际做过的检查。所有要求满足、文件版本一致、问题关闭后才能 status=checked。检查未通过就保留 draft，并交付已完成部分和影响结果的缺口。

学习中心的已复核表示已记录的检查通过，不保证答案绝对正确，也不代表 Canvas 已提交。课程截止时间/提交状态来自 Canvas，草稿完成状态独立记录；只有用户明确要求且流程允许才执行提交。
